The OpenAI adapter works against three surfaces:

- Chat completions (`gpt-4o`, `gpt-4.1`, `gpt-5`)
- Realtime API (voice)
- Codex CLI (via its MCP support — see the [MCP guide](/docs/mcp))

## Install

```bash
bun add @smaran/sdk @smaran/adapter-openai openai
```

## Chat completions

```ts
import OpenAI from "openai"
import { OpenAIAdapter } from "@smaran/adapter-openai"
import { createMemoryClient } from "@smaran/sdk"

const smaran = createMemoryClient({ apiKey: process.env.SMARAN_API_KEY })
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY })
const memory = new OpenAIAdapter(smaran, { sessionId: "sess_abc" })

const completion = await memory.wrap(openai).chat.completions.create({
  model: "gpt-4o",
  messages: [{ role: "user", content: "Where did I say I moved?" }],
})
```

`memory.wrap()` proxies the OpenAI client so every `create()` call gets Smaran context injected before the request and any tool calls to `smaran_save` / `smaran_recall` handled inline.

## Realtime API (voice)

```ts
import { OpenAIRealtimeAdapter } from "@smaran/adapter-openai/realtime"

const rt = new OpenAIRealtimeAdapter(smaran, sessionId)
realtimeSession.on("input_audio_buffer.committed", rt.onUserTurn)
realtimeSession.on("response.done", rt.onAgentTurn)
```

The realtime adapter uses partial ingestion so recall context is ready by the time the LLM starts speaking.

## Codex CLI

Codex CLI supports MCP servers out of the box. See the [MCP setup](/docs/mcp#wire-it-into-the-codex-cli) for a two-line config that gives every `codex` command the same memory as your desktop Claude.
