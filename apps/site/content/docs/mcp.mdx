Smaran ships a Model Context Protocol server that surfaces memory tools inside any MCP-aware client — Claude Desktop, Cursor, Windsurf, the Codex CLI, the Gemini CLI, or anything else that speaks MCP.

## Install

```bash
bun add -g @smaran/mcp
# or run without installing
bunx @smaran/mcp --api-key sk_...
```

## Wire it into Claude Desktop

Edit `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) or `%APPDATA%\Claude\claude_desktop_config.json` (Windows):

```json
{
  "mcpServers": {
    "smaran": {
      "command": "bunx",
      "args": ["@smaran/mcp"],
      "env": {
        "SMARAN_API_KEY": "sk_...",
        "SMARAN_BASE_URL": "https://api.smaran.dev"
      }
    }
  }
}
```

Restart Claude Desktop. You should see `smaran` in the connected servers list and three tools become available:

- `memory_save` — save a fact
- `memory_recall` — search past memories
- `memory_forget` — soft-delete a memory (audit log kept)

## Wire it into Cursor

Cursor uses the same MCP config format. Add to Settings → MCP:

```json
{
  "smaran": {
    "command": "bunx",
    "args": ["@smaran/mcp"],
    "env": { "SMARAN_API_KEY": "sk_..." }
  }
}
```

## Wire it into the Codex CLI

Codex CLI reads `~/.codex/mcp.json`:

```json
{
  "servers": {
    "smaran": {
      "command": "bunx",
      "args": ["@smaran/mcp"]
    }
  }
}
```

Then `codex chat` will have the memory tools in-scope.

## Scoping to a session

The MCP tools default to a fresh session ID per client boot, so different chats don't leak into each other. Pass a stable `sessionId` in the tool call to reuse memory across restarts:

```
memory_save({ text: "the user prefers monospace fonts", sessionId: "u_alice_prefs" })
```

<Callout tone="note" title="Local sandbox mode">
Point `SMARAN_BASE_URL` at `http://localhost:8787` and skip the API key entirely to run the MCP server against your local sandbox — perfect for testing tool calls without cloud roundtrips.
</Callout>
