The fastest way to try Smaran is the local sandbox. It runs a full memory stack in-process — normalizer, self-correction, ephemeral vector store — on a single Bun command. No account, no API key, no cloud infra.

## Prerequisites

You need Bun `1.3.6` or newer and Node `20+`. Clone the repo, install once at the root, and you're ready.

```bash
git clone https://github.com/Ayushpani/smaran
cd smaran
bun install
```

<Callout tone="note" title="Why at the root?">
Smaran is a Bun workspace — dependencies get hoisted from the top-level `package.json`. Running `bun install` inside a nested app won't wire up the shared binaries.
</Callout>

## Start the sandbox

From the repo root:

```bash
bun run try
```

You should see:

```
✓ sandbox on :8787 · in-process store
✓ /v1/memories  /v1/recall  /v1/ingest/*
```

That's it. There is now a full Smaran server running on `localhost:8787` with an in-memory store — perfect for prototyping without touching Postgres.

## Save your first memory

In a second terminal, POST some text:

```bash
curl -sX POST localhost:8787/v1/memories \
  -H "Authorization: Bearer sk_local_dev" \
  -H "Content-Type: application/json" \
  -d '{"text":"confirm my order — one two three four, actually four three two one"}'
```

The response:

```json
{
  "saved": true,
  "text": "confirm my order four three two one",
  "corrections": [{ "kind": "replace", "retracted": "one two three four", "kept": "four three two one" }],
  "latency_ms": 1.8
}
```

Note what happened: the retraction cue (`actually`) was detected, the wrong value was **discarded before hitting storage**, and only the corrected form was persisted. This is the core promise of Smaran.

## Recall it

```bash
curl -sX POST localhost:8787/v1/recall \
  -H "Authorization: Bearer sk_local_dev" \
  -H "Content-Type: application/json" \
  -d '{"query":"what did the caller confirm"}'
```

Returns the corrected value, along with cosine similarity, source metadata, and a `latency_ms` under 3.

Memories saved to the sandbox live only until you stop the process. For persistence, set `STORE=supabase` and provide a `DATABASE_URL` — see the self-host guide.
