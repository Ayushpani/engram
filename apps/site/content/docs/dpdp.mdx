Smaran is built to be a lawful processor of personal data under India's DPDP Act. This page describes how — and where the responsibility lines fall between us and you.

## Roles

- **You** are the **Data Fiduciary** — the entity deciding what data gets collected and why.
- **Smaran** is a **Data Processor** — we store and retrieve what you send us, on your instructions.

If you're building a voice agent that captures customer information, you own the notice/consent flow with the end user. We give you the tools to store, retrieve, and delete that data on your instructions.

## Data flow

Every memory carries three identifiers:

- `tenantId` — your organization
- `sessionId` — one conversation or caller
- `userId` (optional) — a stable end-user identifier

All queries are scoped by `tenantId` at the database layer. Cross-tenant access is impossible by construction, not by policy.

## Data residency

Self-hosted: entirely on your infrastructure. Hosted API: Bangalore region only (`ap-south-1` Postgres, Cloudflare's Indian POPs for edge cache). We do not replicate data outside India.

## Retention

Defaults to indefinite storage — you're expected to delete when the underlying business purpose ends. To purge:

```bash
# Delete every memory for one session
curl -X DELETE https://api.smaran.dev/v1/sessions/sess_abc \
  -H "Authorization: Bearer sk_..."

# Delete every memory for one end user across all their sessions
curl -X DELETE https://api.smaran.dev/v1/users/u_alice \
  -H "Authorization: Bearer sk_..."
```

Both are hard deletes — the row is removed and the audit log records the deletion. The pgvector index is compacted on the next VACUUM.

## Right to correction

The DPDP Act requires you to let end users correct their data. Smaran's `memory_update` endpoint lets you overwrite the `text` field on any memory; the previous value goes to a `memory_history` table (retained 90 days for audit, then purged).

## Grievance officer

For the hosted API, our grievance officer is reachable at `dpdp@smaran.dev` — SLA is 15 days per the Act.

<Callout tone="warn" title="What Smaran does not do">
We do not classify, redact, or filter PII before storage. If you don't want SSNs / Aadhaar / phone numbers in the graph, redact them at your edge before calling `save`. The SDK ships `redactPII(text)` for the common patterns — see the SDK reference.
</Callout>

## Sub-processors

The hosted API uses:

- **Supabase** (Postgres + pgvector) — data at rest, ap-south-1
- **Cloudflare** (Workers, KV, Hyperdrive) — edge cache + HTTP layer
- **Sentry** (self-hosted, ap-south-1) — error reporting, no memory text ever leaves

Each is contractually a sub-processor under the DPDP Act. The current list is published in the tenant admin console and updated on any change.
